# 배드민턴 영상 코치 사용 설명서

문서 기준: 2026-11-16 / Open WebUI Pipe 4.3.0 / 대용량 업로더 2.
현재 코드의 동작을 설명합니다. 개발 구조와 API는 [상세 설계서](DETAILED_DESIGN.md), 시험 이력과 남은 검증은 [검증 기록](../VALIDATION.md)을 참고하세요.

## 1. 무엇을 할 수 있나요

휴대폰으로 찍은 배드민턴 영상을 채팅에 첨부하고, 경기 운영·기술·자세를 질문하는 개인용 코치입니다. 영상 전체 리뷰, 특정 장면의 정밀 확인, 두 영상의 짧은 동작 비교, 일반 배드민턴 질문을 지원합니다. 새 채팅에서도 같은 계정의 프로필과 이전 코칭 기록을 참고합니다.

경기 리뷰는 다음 다섯 항목으로 정리합니다.

1. 경기 전반의 특징
2. 영상에서 관찰되는 수행 수준과 판단 근거
3. 잘한 점과 해당 장면
4. 아쉬운 점과 해당 장면
5. 개선 우선순위·바꿀 행동·연습 방법·다음 영상에서 확인할 기준

수준은 해당 영상에서 보이는 수행을 바탕으로 한 추정입니다. 공식 급수 판정, 정확한 득실점 집계, 셔틀 속도나 악력 측정은 제공하지 않습니다. 개인 강습과 난타는 경기 리포트와 다른 기준으로 분석합니다.

## 2. 평소 사용하는 가장 짧은 순서

1. PC를 켜고 Windows에 로그인합니다.
2. 바탕화면의 **배드민턴 코치 실행** 또는 프로젝트의 **지금실행.cmd**를 더블클릭합니다.
3. 휴대폰에서 Tailscale을 켜고 미리 저장한 개인 HTTPS 주소를 엽니다.
4. Open WebUI에 로그인하고 **배드민턴 코치** 모델의 일반 채팅을 엽니다.
5. `+` → 파일 첨부에서 영상을 선택합니다. 업로드 완료까지 기다립니다.
6. 자신이 누구인지와 원하는 분석을 함께 적습니다.
7. 분석 중 화면을 닫았다면 같은 채팅에서 **결과**를 입력합니다.

처음에는 다음처럼 요청하면 됩니다.

> 경기 영상이야. 검은 상하의를 입고 가까운 코트에 있는 사람이 나야. 경기 운영을 중심으로 전체 특징, 내 수준, 잘한 점, 아쉬운 점, 개선 계획을 리포트로 정리해줘.

영상 업로드와 분석은 별도 단계입니다. **업로드 중에는 휴대폰 브라우저를 열어 두세요.** 업로드가 끝나고 시작된 분석은 브라우저 연결이 끊겨도 PC에서 계속됩니다. PC 전원과 네트워크는 유지해야 합니다.

## 3. 처음 설치하는 PC

이미 구성된 PC에서는 이 절을 다시 수행할 필요가 없습니다. 현재 지원 기준은 Windows, Python 3.12, 안드로이드 Chrome, 개인 사용자 1명입니다.

### 3.1 프로그램과 패키지

- Python 3.12
- FFmpeg와 FFprobe 실행 파일
- 원격 사용 시 PC·휴대폰의 Tailscale
- 모델 API를 호출할 수 있는 OpenAI API 키

프로젝트 폴더의 PowerShell에서 실행합니다.

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.lock.txt
```

`requirements.lock.txt`는 개발 PC의 고정 버전 목록입니다. 다른 OS나 다른 Python 버전에서의 설치를 보장하는 범용 패키지 목록은 아닙니다. `.cmd` 실행 파일과 Windows 자격 증명·바로가기 기능도 Windows 기준입니다.

FFmpeg·FFprobe는 저장소에 포함하지 않습니다. 실행 파일이 PATH에 있으면 자동으로 찾습니다. 별도 위치라면 현재 PowerShell에서 다음과 같이 지정합니다.

```powershell
$env:FFMPEG_PATH = 'C:\Tools\ffmpeg\bin\ffmpeg.exe'
$env:FFPROBE_PATH = 'C:\Tools\ffmpeg\bin\ffprobe.exe'
```

더블클릭 실행에도 같은 경로를 쓰려면 Windows 사용자 환경 변수에 두 값을 등록하고 새로 실행하세요. 프로그램은 명시한 경로, `%LOCALAPPDATA%\hermes\tools`의 기존 설치, PATH 순서로 찾습니다. 기본 native 모드에는 Hermes 설치가 필요하지 않습니다.

### 3.2 키 등록과 첫 실행

1. **인증등록.cmd**를 실행하고 화면에 API 키를 입력합니다. 채팅이나 Git 파일에 키를 적지 않습니다.
2. 아래 명령으로 Open WebUI 플러그인을 설치하고 실행합니다.

```powershell
.\.venv\Scripts\python.exe -m badminton.operations setup
.\.venv\Scripts\python.exe -m badminton.operations shortcut
.\.venv\Scripts\python.exe -m badminton.operations launch
```

3. PC에서 `http://127.0.0.1:8080`을 열어 최초 관리자 계정을 만듭니다. 최초 계정 이후 신규 가입은 닫힌 설정으로 운영합니다.
4. **배드민턴 코치** 모델을 선택하고 일반 질문으로 시작합니다.

API 키는 Windows 자격 증명의 `BadmintonAgent/openai_api_key`에 저장합니다. 코드에는 `OPENAI_API_KEY` 환경 변수 우선과 기존 `CareerScout/openai_api_key` 읽기 대안도 있습니다. 기존 키를 새 파일로 복사하지 않습니다.

### 3.3 집 밖 휴대폰 접속

1. PC와 휴대폰 Tailscale에서 같은 계정으로 로그인합니다.
2. PC에서 **휴대폰연결.cmd**를 실행합니다.
3. 최초 설정에서 안내가 나오면 Tailscale의 MagicDNS·HTTPS/Serve 설정을 완료합니다.
4. 출력된 `https://<PC이름>.<개인네트워크>.ts.net` 주소를 휴대폰 Chrome으로 엽니다.
5. Open WebUI 계정으로 로그인하고 북마크합니다.
6. 와이파이를 끄고 LTE·5G에서 접속을 확인합니다.

Serve 설정을 직접 해야 하는 환경에서는 다음 명령을 사용합니다.

```powershell
tailscale serve --bg http://127.0.0.1:8080
```

이 주소는 같은 Tailscale 네트워크에서 접속하는 개인 주소입니다. 공개 인터넷 사이트로 발행하는 구성은 아닙니다. PC가 꺼졌거나 절전 상태라면 접속할 수 없습니다. 현재 PC의 실제 주소는 **상태확인.cmd** 또는 `%LOCALAPPDATA%\BadmintonAgent\remote-url.txt`에서 확인하세요.

## 4. 영상 올리기와 이어 올리기

| 항목 | 현재 동작 |
|---|---|
| 권장 영상 | 15분 이내 경기, MP4 또는 MOV |
| 설정된 상한 | 파일당 4GiB, 60분 |
| 추가 허용 확장자 | M4V, WEBM, AVI, MKV; 실제 내용은 FFprobe로 검증 |
| 검증한 촬영 조건 | H.264·HEVC, 세로·회전 메타데이터, 가변 프레임레이트 |
| 32MiB 이상 영상 | 4MiB씩 분할 전송, 조각별 검증, 저장 위치 조회·재시도 |
| 작은 영상 | 기존 Open WebUI 첨부 경로 |
| 분석 등록 시점 | 전송 완료·영상 검증 후 |

일반 채팅에서 첨부하세요. **임시 채팅은 지원하지 않습니다.** 임시 채팅은 브라우저 자체 파일 처리 경로를 사용할 수 있습니다.

큰 파일은 화면 하단에 파일명, 진행률, 전송량, 재연결 또는 등록 확인 상태가 나옵니다. 연결이 잠시 끊기면 자동으로 다시 확인합니다. 계속 실패했거나 페이지를 새로고침했다면 **같은 원본 파일을 다시 선택**하세요. 서버에 저장된 위치부터 이어 보낼 수 있습니다. 편집하거나 새로 내보낸 파일은 별개 파일로 취급될 수 있습니다.

완료되지 않은 임시 업로드는 마지막 저장에서 24시간이 지난 뒤 서비스 시작 시 정리합니다. 장기간 뒤에는 다시 전송해야 할 수 있습니다. 휴대폰이 브라우저를 종료했을 때 백그라운드 전송을 보장하지 않습니다. 업로더를 업데이트한 직후에는 채팅 페이지를 한 번 새로고침하세요.

4GiB는 설정 한도입니다. 모든 휴대폰·네트워크에서 4GiB 전송을 완료했다는 의미가 아닙니다. 검증 범위는 [시험 안내](#12-검증과-현재-한계)를 참고하세요.

## 5. 분석 목적에 맞게 요청하기

### 경기 운영·전술

> 복식 경기야. 빨간 상의가 나야. 공격·수비 전환, 위치 선정, 타구 후 복귀를 중심으로 경기 전체 리포트를 작성해줘.

좋은 장면과 개선할 장면의 시각, 행동의 영향, 다음에 바꿀 행동을 함께 요청할 수 있습니다. 반복되는 습관을 말하려면 서로 다른 플레이 구간의 근거가 필요합니다.

### 기술·자세·임팩트

> 이 경기에서 흰색 상의 선수의 스매시 타점과 준비 자세를 봐줘.

> 00:19~00:22 사이 스윙에서 손과 라켓을 자세히 확인해줘.

스매시·드라이브·푸시·언더·리시브·서브리시브·수비 중 궁금한 동작을 지정하세요. 원본 프레임과 확대가 필요한 질문은 짧은 구간에 집중합니다. 실제 접촉점이나 손가락이 흐리면 확인 가능한 몸통·이동·준비 자세를 중심으로 설명합니다.

### 두 영상 비교

두 파일을 같은 메시지에 첨부하고 파일명을 지정하세요.

> A.mp4와 B.mp4에서 내 스매시 타점을 비교해줘. 두 영상 모두 검은 옷이 나야.

새 첨부 묶음이 후속 질문의 현재 대상이 됩니다. 이전 첨부와 새 첨부를 자동으로 전부 섞지 않습니다. 전체 경기 리뷰는 한 번에 영상 1개 기준이며, 두 영상의 짧은 동작 비교는 별도 지원합니다.

### 강습·난타

> 개인 강습 영상이야. 코치가 아니라 파란 상의의 수강생이 나야. 스매시 동작을 어떻게 수행했고 무엇부터 교정하면 좋을지 알려줘.

> 드라이브 난타 영상이야. 반복 안정성과 준비 자세가 무너지는 패턴을 분석해줘.

강습은 동작 수행과 교정 과제, 난타는 반복 일관성과 흔들리는 조건을 중심으로 정리합니다. 현재 음성 전사는 없으므로 코치가 실제로 말한 내용을 분석하지 않습니다.

### 영상 없는 질문과 후속 질문

- “스매시의 기본 그립을 설명해줘.” → 일반 설명
- “방금 개선점을 쉽게 풀어서 말해줘.” → 저장된 근거를 이용한 설명
- “아까 말한 장면의 타점도 새로 확인해줘.” → 필요한 장면 추가 확인
- “과거 경기 조언과 내 목표를 바탕으로 오늘 10분 연습을 추천해줘.” → 개인 기억을 참고한 답변

모든 질문마다 영상을 전체 재분석하는 방식은 아닙니다. 대상이나 목적이 불분명할 때만 짧게 확인합니다. 영상마다 본인의 옷·위치를 지정하며, 예전 옷 색을 새 영상의 본인으로 자동 적용하지 않습니다.

## 6. 진행 상태·결과·취소·재개

| 채팅 명령 | 의미와 비용 |
|---|---|
| 결과 / 상태 / /result / /status | 진행 중 최신 요약 또는 저장된 보고서 조회. 새 모델 호출 없음 |
| 취소 / /cancel | 진행 중 전체 리뷰 우선 취소, 없으면 마지막 작업 취소 요청 |
| 리뷰계속 | 같은 리뷰의 남은 기존 예산으로 재개 |
| 리뷰계속 1.00 | 사용자 지정 추가 예산 USD 1.00을 같은 리뷰에 더해 재개 |
| 영상목록 / /videos | 현재 채팅의 영상 번호 조회 |
| 영상삭제 1 | 목록 1번 영상의 분석 저장 원본·관련 기록과 Open WebUI 첨부 삭제 시도 |

`결과`는 전체 리뷰가 있으면 그 리뷰를 우선 조회합니다. 화면을 다시 열었다고 기존 채팅 본문이 자동 갱신된다고 가정하지 말고 명령으로 조회하세요.

취소는 다음 안전 지점에 적용됩니다. 이미 시작된 API 호출의 사용료를 취소하거나 반환시키지는 않습니다. PC·서비스 재시작 뒤에는 완료된 구간을 보존하고, 실행 여부가 불확실한 호출은 자동 재전송하지 않습니다. 재개가 막히면 [문제 해결](#10-문제-해결)을 참고하세요.

같은 메시지 요청 ID의 중복 전달은 한 작업으로 처리합니다. 사용자가 새 메시지로 같은 질문을 보내면 별도 요청일 수 있으므로, 진행 확인에는 `결과`를 사용하세요.

## 7. 새 채팅에서도 이어지는 기억

개인 기억은 같은 Open WebUI 계정 기준입니다. 주손·단복식·목표 같은 직접 진술, 과거 분석 에피소드, 실제 연습 소감을 나누어 저장합니다. 모든 채팅 문장을 무제한 저장하거나 매번 전부 모델에 보내지는 않습니다.

| 명령 | 사용 예 |
|---|---|
| 기억목록 | 저장 내용과 수정·삭제용 ID 확인 |
| 기억저장 내용 | 기억저장 나는 복식 위주이며 풋워크 개선이 목표야 |
| 기억수정 ID 내용 | 기억수정 abc123 나는 왼손잡이야 |
| 기억삭제 ID | 기억삭제 abc123 |
| 성장기록 내용 | 성장기록 오늘 복귀 첫 스텝 연습을 10분 했어 |
| 기억전체삭제 | 과거 개인 기억 전체 삭제 및 과거 기록 자동 재가져오기 차단 |
| 기억끄기 / 기억켜기 | 개인 기억의 답변 활용과 자동 저장 끄기·켜기 |

실제 ID는 `기억목록`에 나온 값을 사용하세요. 이 명령 자체에는 새 모델 호출이 없습니다. 기억을 꺼도 이미 저장된 기억은 목록에서 조회·삭제할 수 있습니다. 꺼 둔 기간의 분석을 다시 켰다고 자동 편입하지 않습니다.

새 채팅은 과거 코칭의 **텍스트 기록**을 참고할 수 있지만, 다른 채팅의 영상 파일을 직접 여는 권한은 얻지 않습니다. 이전 영상의 새 장면을 확인하려면 새 채팅에 그 영상을 첨부해야 합니다. 연습 소감은 자기보고이며 영상으로 확인한 개선과 구분합니다.

## 8. 비용은 어디에 발생하나요

| 작업 | 모델 API 비용 |
|---|---|
| 파일 전송·디스크 저장·FFprobe·프레임 추출·회전·크롭·이동 후보 계산 | 없음. PC 자원 사용 |
| 이미지 내용을 모델로 읽기·요청 분류·일반 답변·코칭·리포트 생성 | 사용량에 따른 비용 발생 |
| 결과·상태·기억 관리 명령 | 새 모델 호출 없음 |
| 저장 관찰 재사용 후 새로운 자연어 답변 생성 | 이미지 재판독은 줄지만 새 답변 비용은 발생 가능 |

현재 기본 모델은 `badminton/pricing.py`와 설정의 `gpt-6-luna`입니다. **최초 전체 리뷰 상한은 영상당 USD 3.50**이며 정액 요금이 아닙니다. 일반 질문과 후속 질문의 모델 비용은 이 리뷰 상한과 별도입니다. 업로드만 했다고 자동으로 USD 3.50이 청구되는 것은 아닙니다.

전체 리뷰는 남은 비용으로 판독이 불가능하면 부분 리뷰로 끝납니다. 자동으로 새 USD 3.50 작업을 만들거나 해상도·밀도를 낮추지 않습니다. 추가 예산은 `리뷰계속 1.00`처럼 명시했을 때만 반영합니다. 이미 완료된 리뷰에 이 명령을 입력해 예산을 더하거나 재분석하지는 않습니다.

진행 표시에는 리뷰의 사용 금액·상한이 나오며 상세 API에는 미정산 예약 금액도 있습니다. 실제 입력·출력·캐시 사용량, 모델, 호출별 요금표는 로컬 `agent.db`의 `calls`에 기록합니다. 요금표는 코드에 등록한 스냅샷이므로 서비스 사업자의 최신 청구 단가와 운영자가 별도로 대조해야 합니다. 세금·환율을 포함한 원화 확정 청구액은 계산하지 않습니다.

## 9. 실행 버튼과 데이터 관리

| 파일 | 역할 |
|---|---|
| 지금실행.cmd | 두 서비스 시작·준비 확인·브라우저 열기 |
| 중지.cmd | 서비스 중지. 진행 중 분석이 있다면 먼저 결과 확인 또는 취소 권장 |
| 상태확인.cmd | 서버·작업·모델·디스크·휴대폰 주소·절전 상태 진단 |
| 설정적용.cmd | 서비스 중지 → 플러그인 설치/설정 반영 → 재시작 |
| 인증등록.cmd | API 키를 Windows 자격 증명에 등록 |
| 휴대폰연결.cmd | Tailscale 개인 HTTPS 연결 설정 |
| 로그인시자동실행.cmd | Windows 로그인 시 서버 시작 등록 |
| 자동실행해제.cmd | 로그인 자동 시작 해제 |

기본 실행 데이터는 **`%LOCALAPPDATA%\BadmintonAgent`**에 보관합니다. 코드 폴더가 OneDrive에 있어도 영상·DB·키·로그는 기본적으로 이 데이터 폴더에 있습니다. `BADMINTON_DATA_DIR`를 바꾼 개발 환경은 예외입니다.

- `webui/`: 계정·채팅 DB와 업로드 원본
- `originals/`: 분석용으로 별도 보존한 원본
- `agent.db`: 작업·관찰·리포트·비용·개인 기억
- `uploads.db`: 이어 올리기 세션·저장 위치
- `cache/`: 추출 이미지·재생성 가능한 캐시
- `logs/`, `backups/`: 진단 기록·백업
- `service.key`, `webui.secret`: 내부 인증 비밀값

같은 영상이 업로드 저장소와 분석 저장소에 각각 존재하므로 파일 크기의 약 두 배에 캐시 공간을 더해 확보하세요. 원본과 분석 결과를 정기 자동 삭제하지 않습니다. 캐시는 기본 7일 정리 대상입니다.

백업은 작업 완료 후 `중지.cmd`로 서비스를 멈추고 데이터 폴더 전체를 별도 위치에 복사하세요. 복구도 중지 상태에서 수행한 뒤 다시 실행합니다. Windows 자격 증명에 저장된 API 키는 폴더 복사로 이전되지 않으므로 새 PC에서는 재등록해야 합니다. 이 폴더를 GitHub에 올리지 마세요.

영상삭제는 관련 분석 원본·작업·리뷰·기억을 지우며 Open WebUI 첨부 삭제도 시도합니다. 이미 화면에 표시된 채팅 답변, 백업, 재생성 가능한 일부 캐시는 별도 정리가 필요할 수 있습니다. 채팅을 먼저 지우면 영상삭제 명령을 사용할 경로가 사라질 수 있으므로 필요한 원본 삭제를 먼저 하세요. 다른 채팅에 별도로 등록한 같은 내용의 영상은 그 채팅에서 관리합니다.

## 10. 문제 해결

| 증상 | 먼저 할 일 |
|---|---|
| 휴대폰에서 주소가 열리지 않음 | PC 전원·절전·서비스 상태, 양쪽 Tailscale 로그인, 저장 주소 확인 |
| PC에서도 UI가 열리지 않음 | 지금실행.cmd 실행 후 준비 메시지 확인, 상태확인.cmd와 webui 로그 확인 |
| 업로드 실패 | 페이지 새로고침 후 같은 원본 재선택. 파일 크기·길이·진행률과 표시된 오류 기록 |
| 로그인 만료 | Open WebUI 재로그인 후 같은 원본 재선택 |
| 디스크 부족 | 데이터 드라이브 여유 확보. 영상 두 사본·캐시 공간 고려 |
| FFmpeg/FFprobe 없음 | PATH 또는 두 실행 파일 환경 변수 확인 후 서비스 재실행 |
| 손상된 영상 | 휴대폰에서 원본 재생 확인, 온전한 MP4/MOV를 다시 선택 |
| 업로드했는데 선수 질문이 나옴 | 옷·코트 위치와 본인이 누구인지 지정 |
| 영상 전체 대신 한 장면 답변 | “경기 전체 리포트, 경기 운영 중심”처럼 범위를 명시. 저장 결과 재설명인지 새 관찰 요청인지 구분 |
| 채팅 연결이 끊김 | 같은 채팅에서 결과 조회. 분석을 새 메시지로 반복 요청하지 않기 |
| API 인증·권한·사용 한도 오류 | 인증등록.cmd의 키와 계정 사용 가능 상태 확인. 키를 로그나 채팅에 붙이지 않기 |
| 예산 부족·부분 리뷰 | 확인 범위·사용/예약 금액 확인 후 리뷰계속. 예산 추가는 금액을 명시 |
| 실행 여부가 불확실한 API 호출 | 무조건 재시도하지 말고 호출 기록·사업자 사용량 확인. 현재 자동 해결 명령은 없음 |
| 과거 기억이 잘못됨 | 기억목록 → 기억수정 또는 기억삭제 |

주요 로그는 `logs/agent.log`, `logs/agent-error.log`, `logs/webui.log`, `logs/webui-error.log`, `logs/upload-events.jsonl`입니다. 로그에는 개인 파일명·질문·분석 맥락이 포함될 수 있으므로 필요한 부분만 확인하고 그대로 공개하지 마세요.

## 11. 업데이트와 개발 시험

작업 완료 → 데이터 백업 → 중지 → 코드 업데이트 → 플러그인 설정 적용 → 실행 순서로 진행합니다. 현재 설치된 고정 의존성을 다시 설치할 필요가 있는지는 변경 내역을 보고 판단합니다.

```powershell
$env:PYTEST_DISABLE_PLUGIN_AUTOLOAD = '1'
.\.venv\Scripts\python.exe -m pytest -q
```

자동 회귀 시험은 합성 영상과 모의 모델을 사용하며 실제 모델 API를 호출하지 않습니다. 첫 줄은 이 시험에 불필요한 외부 pytest 플러그인 자동 로딩을 제외합니다. Windows 정책에 차단된 부가 DLL을 불러오는 경우에도 정책을 변경하지 않고 프로젝트 시험만 실행하기 위한 설정입니다. 다음 시험은 구분해서 실행하세요.

| 시험 | 성격 |
|---|---|
| scripts.large_upload_smoke | 격리 Chrome 대용량 전송·응답 유실·새로고침 복구 시험. 모델 생성 호출 0, 수 GiB 디스크와 시험 포트 필요 |
| scripts.verify_match_deployment | 이 PC의 기존 저장 리뷰·개인 HTTPS 설정을 전제로 하는 무료 조회 검증. 신규 설치에서 바로 통과하는 범용 시험 아님 |
| scripts.live_smoke / e2e_webui / precision_smoke / match_review_acceptance 등 | 실제 모델 호출·요금이 발생할 수 있는 개발자용 시험 |
| scripts.publish_* / finalize_match_review | 기존 기록을 옮기거나 재검증하는 유지보수 도구. 일반 실행·업데이트 절차에 사용하지 않음 |

완료된 실제 영상 시험을 단순 확인하기 위해 다시 돌리지 말고 저장된 보고서와 검증 기록을 조회하세요.

## 12. 검증과 현재 한계

자동 시험은 문서화 시점 **131개 통과**입니다. 실제 18분 52초 영상의 고유 2,265장·63구간 판독과 원본 시각 대조를 확인했습니다. 전체 2fps 시간대 판독이 완료되었다고 모든 타구·실수를 빠짐없이 찾아냈거나 코칭 의미가 모두 정확하다는 뜻은 아닙니다.

대용량 전송은 Chrome에서 1.55GiB 시험 파일을 올리고 응답 유실·페이지 새로고침·이어 올리기·저장 해시·채팅 연결을 검증했습니다. 해당 파일은 유효한 짧은 MP4에 표준 패딩을 추가한 전송 시험용입니다. 이 시험을 실제 경기 영상의 디코딩 정확도나 물리 휴대폰 5G 전송 성공으로 해석하지 않습니다.

카메라 각도·가림·모션 블러 때문에 손가락과 정확한 접촉 순간을 확인하지 못할 수 있습니다. 그때도 관찰 가능한 자세·이동·준비·복귀는 설명하되, 관찰과 원인 추정·연습 실험을 구분합니다. 셔틀 추적은 로컬 이동 후보이며 전용 학습 검출기나 속도 계측기가 아닙니다.

현재 기본 harness는 **native**입니다. Hermes와 MCP 연결 코드는 있지만 이 Windows PC의 서명 정책 차단으로 Hermes 통합 실행은 검증되지 않았습니다. 보안 정책을 우회하지 않습니다.
